# 배포 안내 — 팀장 리더십 리플렉션 v4 (Vercel)

이 문서는 기업문화팀이 GitHub·Vercel·Supabase 화면에서 직접 할 일을 순서대로 적었습니다.
코드 쪽 준비(지역 `icn1`, 보안 헤더, DB 주소 처리, 배포 제외 파일)는 끝나 있습니다.

## 0. 배포 전 확인 (SPEC 10장)

| 확인 | 내용 | 담당 |
|---|---|---|
| Vercel 요금제 | Hobby 플랜의 상업적 사용 제한을 **Vercel 이용 약관(https://vercel.com/legal/terms)** 에서 확인하고, 회사 업무용이면 Pro 등 결제 주체를 정한다. (요금제 안내·공정 사용 페이지에는 이 내용이 적혀 있지 않아 약관 원문 확인이 필요) | 기업문화팀 |
| 사내 정보보안 검토 | 사외 클라우드(Vercel, Supabase)에 교육 응답·직접 쓴 문장이 저장된다. 개인정보(이름·사번·이메일·소속·IP)는 앱 DB에 없음. Vercel 플랫폼 요청 로그(IP 포함)는 앱 DB와 별개로 Vercel 에 남는다 | 정보보안 |
| 사내 접속 | 사내 메신저·메일 앱 안 브라우저, 사내 프록시에서 `*.vercel.app` 접속이 막히지 않는지 | IT |
| DB 백업 | Supabase 요금제별 백업 방식(주기·보관 기간)을 Supabase 문서에서 확인 | 기업문화팀 |

## 1. DB 만들기 — Supabase, 서울 리전 2개

DB 제공사로 **Supabase** 를 쓴다(이유는 README 'DB 제공사 선택').
**시범 운영(Preview)** 과 **본 운영(Production)** 을 서로 다른 프로젝트로 만든다(시범 응답이 본 데이터에 섞이지 않게).

| 프로젝트 이름(예) | 연결할 Vercel 환경 | 리전 |
|---|---|---|
| leader-reflection-pilot | Preview | Northeast Asia (Seoul) `ap-northeast-2` |
| leader-reflection-prod | Production | Northeast Asia (Seoul) `ap-northeast-2` |

만드는 방법은 둘 중 하나:
- **A. Vercel Marketplace 로 만들기** (SPEC 기본안): Vercel 프로젝트 → Storage(또는 Integrations) → Supabase.
  만들 때 **리전을 Seoul 로 고를 수 있는지**, 그 DB 를 **Preview / Production 환경에 따로 연결할 수 있는지** 확인한다.
  연결하면 `POSTGRES_URL` 이 자동으로 들어온다. 앱은 `DATABASE_URL` 이 없으면 `POSTGRES_URL` 을 쓴다.
- **B. Supabase 에서 직접 만들고 주소만 넣기**: A 에서 서울 리전이나 환경별 연결이 안 되면 이 방법.
  supabase.com 에서 프로젝트를 만들고(리전 Seoul), Connect → **Transaction pooler**(포트 6543) 주소를 복사해
  Vercel 환경 변수 `DATABASE_URL` 에 **환경별로** 넣는다(아래 3).

주소에 붙는 `supa=...` 같은 값은 앱이 알아서 지우고, 암호화 연결(`sslmode=require`)을 붙인다.
테이블은 앱이 처음 요청을 받을 때 자동으로 만든다(따로 SQL 을 실행할 필요 없음).

## 2. GitHub 저장소와 Vercel 프로젝트

1. GitHub 에 **비공개(private)** 저장소를 만들고 이 폴더를 올린다(`main` 브랜치).
2. Vercel → Add New → Project → 그 저장소 Import.
   - Framework: FastAPI 로 자동 인식(진입 파일 `main.py` 의 `app`). Root Directory 는 저장소 맨 위
   - 함수 리전 `icn1`(서울)은 `vercel.json` 에 이미 들어 있다
   - Production Branch: `main`
3. 처음 Import 할 때 만들어지는 Production 배포는 환경 변수를 넣기 전이라 동작하지 않는 것이 정상이다(아래 3을 마치고 다시 배포).

## 3. 환경 변수 (Vercel → Settings → Environment Variables)

**Production 과 Preview 에 서로 다른 값**을 넣는다. 값은 이 저장소·메신저·메일에 남기지 않는다.

| 이름 | Production | Preview(시범) | 비고 |
|---|---|---|---|
| `DATABASE_URL` | prod DB 주소 | pilot DB 주소 | 방법 A 로 연결했으면 `POSTGRES_URL` 이 대신 들어옴 |
| `ENTRY_KEY` | 본 운영 입장 키 | 시범 입장 키 | 영문·숫자·`-`·`_` 8~64자. 관리자 설정에서 바꾸면 그 값이 우선 |
| `ADMIN_PASSWORD_FULL` | 기업문화팀 암호 | 시범용 암호 | 길고 추측하기 어렵게 |
| `ADMIN_PASSWORD_READONLY` | HR 임원 암호 | 시범용 암호 | 전체 권한 암호와 다르게 |
| `SESSION_SECRET` | 무작위 32바이트 이상 | 다른 무작위 값 | 아래 명령으로 만들기 |
| `APP_VERSION` | 예: `4.1.0` | 예: `4.1.0-pilot.1` | 화면 하단 표시, Git 태그와 맞춤. 비우면 커밋 앞 7자리 |

무작위 값 만들기(입장 키·서명 키):

```powershell
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

환경 변수를 바꾼 뒤에는 **다시 배포(Redeploy)** 해야 반영된다.

## 4. 시범 운영 (Preview)

1. `pilot` 브랜치를 GitHub 에 올리면 Preview 배포가 만들어진다. 브랜치 고정 주소(예: `<프로젝트>-git-pilot-<팀>.vercel.app`)를 쓴다.
2. Preview 배포에 Vercel 로그인 화면이 먼저 나오면 Settings → Deployment Protection 설정을 확인한다(시범 참여자가 Vercel 계정이 없으면 Preview 보호를 끄거나 공유 링크 사용).
3. 확인 목록
   - [ ] `/api/health` → `{"ok": true, "db": "postgresql"}`
   - [ ] `/?k=<시범 입장 키>` 로 열림, 키 없이 열면 '안내 메일이나 메신저의 링크로 들어와 주세요'
   - [ ] 처음부터 완료까지 진행, 중간에 닫고 다시 열면 이어 하기
   - [ ] `/admin` 두 암호로 로그인, 읽기 전용은 설정·CSV 가 보이지 않음
   - [ ] 관리자 설정: 차수명, 마감일, 대상 인원
   - [ ] 기기별: iOS Safari, Android Chrome, PC Chrome·Edge, **사내 메신저 안 브라우저, 메일 앱 안 브라우저** —
         PDF 다운받기(앱 안 브라우저에서 파일이 받아지는지), 동료에게 추천하기(링크가 복사되는지), 꽃가루·카운트다운
   - [ ] 앱 안 브라우저로 열면 안내 화면에 '메신저·메일 앱 안에서 열었어요…' 안내가, 완료 화면에 '캡처해 두세요' 한 줄이 나오는지.
         나오지 않는 앱이 있으면 그 앱의 User-Agent 를 알려 주세요(`public/app.js` 의 `browserFamily` 에 추가). 관리자 4.5 기기별 표 아래 '앱 안 브라우저로 연 기기' 수가 늘었는지
   - [ ] 앱 안 브라우저에서 PDF 가 받아지지 않으면: 안내 메일·메신저 문구(아래 4-1)의 '다른 브라우저로 열기'를 꼭 넣는다
4. 시범 운영이 끝나면 관리자 '사용 흐름' 탭의 소요 시간 중앙값으로 안내 화면 '약 n분'을 정한다(본 운영 첫 주에 다시 확인).
5. 시범 응답으로 설정 → '판정 기준값 미리보기'를 보고 본 운영의 판정 기준값을 정한다(한 칸이 70% 이상이면 '쏠림'). 바꾸면 그 뒤 결과부터 적용되므로 본 운영 시작 전에 정한다.

### 4-1. 안내 메일·메신저 문구에 넣을 것 (초안, 2026-11-27)

앱 안 브라우저 제약, 브라우저 저장소 만료, 다른 기기 중복 시작을 줄이기 위한 문장이다. 기업문화팀이 다듬어 쓴다.

> - 링크는 **Chrome·Safari 같은 브라우저**에서 열어 주세요. 메신저·메일 앱 안에서 열리면 오른쪽 위 메뉴의 ‘다른 브라우저로 열기’를 눌러 주세요(앱 안에서는 결과 PDF가 저장되지 않을 수 있어요).
> - 약 n분이면 끝나요. **되도록 한 번에** 끝내 주세요. 중간에 나가면 **처음 연 기기·브라우저**에서만 이어 할 수 있고, 며칠 비워 두면 이어 하기가 끊길 수 있어요.
> - 마지막 화면에서 ‘PDF 다운받기’로 결과를 받아 두면 다음 면담 전에 다시 볼 수 있어요.
> - 이 링크는 대상 팀장님께만 보내 드렸어요. 동료 팀장님께는 마지막 화면의 ‘동료에게 추천하기’를 써 주세요.

## 5. 본 운영 (Production)

1. `pilot` → `main` 병합하면 Production 배포가 만들어진다.
2. Git 태그를 `APP_VERSION` 과 맞춘다(예: `v4.1.0`).
3. 관리자(`/admin`) 설정: 차수명, 마감일, 대상 인원 170, 안내 화면 '약 n분'.
4. 안내 링크: `https://<프로젝트>.vercel.app/?k=<본 운영 입장 키>` — 메일·메신저 모두 같은 링크.
   관리자 설정 → 입장 키 화면에 지금 쓰는 링크가 그대로 표시된다.

## 6. 운영 중

- 입장 키가 밖으로 퍼진 것 같으면: 관리자 설정 → 입장 키 변경 → 새 링크 재발송(예전 링크·추천 링크는 막힘).
  신호: 대시보드 1.1 의 '등록한 리더가 대상 인원보다 많아요' 경고, 4.6 '추천 링크 유입' 기기 수가 대상 인원에 비해 크게 늚
- 시험 응답·같은 사람의 중복 시작: 관리자 설정 → 참여자 삭제(리더명 + 4자리 번호). 참여자 탭(3.1)에서 직접 지은 리더명이 겹치면 '같은 이름 n명' 표시
- 직접 쓴 문장에 구성원 실명이 보이면: 문항 분석 2.8 → 문장 옆 '삭제'(전체 권한)
- 앱 안 브라우저 비율(4.5)이나 기술 오류(4.13)가 늘면: 안내 재발송 때 4-1 의 '다른 브라우저로 열기' 문장을 앞에 둔다
- 다음 차수: 관리자 설정에서 차수 코드를 바꾸면 집계가 새로 시작된다(이전 차수는 상단 차수 선택으로 열람)
- 관리자 로그인 5번 실패 시 10분 동안 **모든 관리자**가 잠긴다(IP 를 저장하지 않으므로 전체 잠금)
